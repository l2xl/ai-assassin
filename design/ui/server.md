# The server

`assassin [--root PATH] [--port N] [--coverage FILE …] [--build-dir DIR] [--no-browser] [--no-reload]` (or `python -m ai_scratcher.assassin_ui`) serves the page, stdlib-only, at `http://127.0.0.1:<port>`: without `--port` the project's own port, one of the 200 above 8712 picked by the sha256 of the resolved project root — the same root, the same port across runs, so the servers of several projects run side by side — the next one of the range (wrapping around) while it is held and an ephemeral port once all are; an explicit `--port` binds exactly that port or fails, `--port 0` picks an ephemeral port and the URL line is flushed for hosts reading it from a pipe. Once it listens the server writes `assassin_server.json` into the project root — its pid, port and token — and removes it when it stops; an `assassin` started on a root whose record names a live process answering `/api/fingerprint` with that token opens the browser at that server's URL and exits instead of starting a second server, while a record whose process is gone or whose server does not answer is ignored and replaced (the engine restarted in place keeps its pid and rewrites the record). The project is `--root`, else `SYNGATE_ROOT`, else the nearest ancestor of the working directory holding `syngate/`, else the working directory itself; when its `syngate/` is missing or holds no item file at any depth, the server bootstraps it with one root item written through the canonical writer and names the file in an `assassin: bootstrapped …` line. The root's UID is the project folder's name upper-cased, every run of characters outside `A-Z`, `0-9` and `_` turned into `-` and the edge dashes stripped (`my-app` → `MY-APP`), `PROJECT` where that is no valid UID; its first line is the first `# ` heading of the project's `README.md`, else the folder's name, followed by the link `[README.md](README.md)` when the file exists; both the test and the review feature are left off. A tree with any item file, even an unparsable one, is never touched. It is loopback-bound and every request needs the per-session token from the printed URL (the Jupyter-style defense for localhost tools that execute commands), a request naming a non-loopback host refused as well; the page runs under a nonce-only `Content-Security-Policy`, the second fence behind the escape-first markdown renderer. Runs (test / review / clear) shell out to the `syngate` code path, so stamping semantics are the terminal's, and fold their records into `syngate_coverage.jsonl` next to the tree, which the page always reads, so a run recolors the statuses without a CI round trip. Chats are kept in `assassin_chats.json` beside it (a `syngate_chats.json` of earlier versions is read while it is absent); both stay untracked. The server settings are read from `assassin_settings.json` beside them at every use, so an edit takes effect without a restart, a missing or malformed file reading as no settings; each feature keeps its own section, the `websurf` one holding the WebSurf host lists, the `connections` one the setup of the OpenAI-compatible API connections. The WebSurf browser extension attaches over a WebSocket at `/websurf` on the same port, carrying the token in its first message rather than in the URL. Whether git is at hand — the `git` command found and the project root in a work tree — is read once at start; while it is, the page's model carries `git` with the uncommitted files, and the fingerprint the page polls covers `HEAD` and the work tree status, so a commit recolors the page as an item edit does.

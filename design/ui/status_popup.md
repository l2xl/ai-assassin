# The common item label and the status popup

Wherever an item is shown — the row, the block's top border — its label is the composite status icon followed by the UID. The icon is one element: a circle filled by the test status (green passed, red failed, grey not run — the page's word for the `unknown` axis value), the review eyes `👀` over it for a standing stamp, the eyes with `❗` (U+2757) laid over their right part, outside the circle and as tall as it, for a violated stamp, nothing for no stamp. The circle's diameter is about 1.15× the glyph font size plus 2px; the eyes (U+1F440) sit shifted toward the circle's right edge so they still mostly overlap it, drawn from the colour emoji fonts (Apple Color Emoji, Segoe UI Emoji, Noto Color Emoji, Twemoji Mozilla). The icon is a button: clicking it in either pane opens the status popup — the status lines (a leaf's bindings with routine, frozen mark and last run; a branch's tally of the leaves below, each failing or not-run leaf a jump link, and its own bindings if any; the item's validation problems, also shown inline in the block), the binding editor of a childless item, the setup editor, the test runs, then the run actions: `▶ Run test` / `▶ Run tests of N leaf items`, `👀 Mark reviewed` / `👀 Mark reviewed with N items below`, `✕ Clear review`. Nothing else on the page shows the status: no second pill on the block, no hover tooltip, no `T` button on the row. With both features off the icon stays, unfilled and without a glyph, since it anchors the run.

A switched-off feature shows nothing of itself, item by item as the switches above each set it: with the test feature off there is no test fill in the icon, no test details and no binding editor in the popup; with the review feature off no review glyph and no review or clear run — the test run stays offered whichever way the switches sit.

The **binding editor** switches a childless item's `test` key on and off and adds or removes named bindings (names `[a-z0-9_]+`, the default binding standing alone); a frozen binding is removed only after a confirmation, and every change is saved as a compare-and-swap of the binding list.

The **setup editor** stands beside it, on every item the test feature reaches and on one carrying a setup: it names where the item's test setup comes from — its own, the item above whose setup holds for it, or the built-in one — and edits the item's own `run` command line, `files` globs, `report` format and `env` lines (`NAME=value`). Saving writes the whole setup and removing drops it, each as a compare-and-swap of the setup through the item edit; a refused setup stays typed with the refusal under it until it is saved or removed.

The **run actions** start the test, review or clear command for the item — review and clear only while the review feature is on, clear only on a reviewed item — streaming the output into the console until the command exits; a run can be stopped there, and a reloaded page re-attaches to the running one. On a branch the test run addresses every leaf below, and the review, after a confirmation, stamps children first, then the branch; a second run is refused while one is active.

A review stamps only the items whose own review does not stand — unstamped, or with a validation problem of their own — `👀 Mark reviewed with N items below` counting them, and a run where none does is refused. While git is at hand it waits for its footprint to be committed: `👀 Mark reviewed` stands disabled, titled with the files, next to `commit first: N files`, and `⎇ Commit with AI` — offered whenever the project holds uncommitted changes — sends `Commit the uncommitted changes of the project.` as a turn of the item's chat, where the AI commits through the git tool. The run then ends with the review commit: the item files it stamped, and nothing else staged, committed as `Review: <subject>` after the one commit since the last review commit — the latest whose subject opens with `Review` or `Reviewed` — or, after several or none, with the message the AI formulates in a turn of the reviewed item's chat (its reply's line opening with `Review`, else its last line so prefixed). The console shows the commit as the run's last lines; the run stays live until it is made and its stop stops the message turn; a stopped run or a failed message turn leaves the stamps uncommitted, the console saying so.
